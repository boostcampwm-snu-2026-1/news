현재 구현 상태를 점검하고, 문제가 없으면 커밋 메시지 초안을 만들어줘.

## 1단계: 품질 점검

아래 항목을 순서대로 확인해. 문제가 하나라도 있으면 **2단계로 넘어가지 말고** 발견한 문제를 나에게 보고해.

1. **에러 체크** — 다음 세 명령을 실행해서 에러가 없는지 확인:
   ```
   npx tsc --noEmit
   pnpm lint
   pnpm build
   ```
   (IDE에서만 뜨는 에러도 놓치지 말 것 — CLAUDE.md 주의사항 참고)

2. **코드 품질** — 변경된 파일을 읽고 아래를 체크:
   - 타입이 `any`로 남아있는 곳은 없는가
   - 불필요한 `console.log`, 죽은 코드, 주석 처리된 코드가 있는가
   - 명백히 더 나은 구현 방법이 있는데 복잡하게 짠 곳은 없는가

3. **스펙 준수** — `docs/DESIGN.md`와 `docs/CHECKLIST.md`를 기준으로:
   - 현재 기능 번호의 구현이 스펙과 일치하는가
   - 빠뜨린 세부 요구사항은 없는가

문제가 남아있으면 목록으로 정리해서 보고하고 여기서 멈춰.

---

## 2단계: 커밋 메시지 초안 작성

1단계에서 문제가 없을 때만 진행.

1. `git diff --staged` 와 `git status` 를 실행해서 이번에 구현한 내용을 파악해.
   - staged가 없으면 `git diff HEAD` 로 확인해.

2. `docs/CHECKLIST.md` 를 읽어서 현재 진행 중인 기능 번호(#숫자)를 파악해. 해당 항목을 `[x]`로 체크해.

3. 아래 형식으로 커밋 메시지 초안을 출력해:

```
<type>: #<기능번호> <제목>

- 확인내용: <이번 커밋에서 구현한 내용을 구체적으로 작성>
- 이해 안 됐던 부분: 
```

규칙:
- `<type>`: feat / fix / refactor / style / chore 중 선택
- `<제목>`: 한 줄, 간결하게
- `확인내용`: 어떤 컴포넌트를 만들었는지, 어떤 로직을 구현했는지 구체적으로
- `이해 안 됐던 부분`: 빈칸으로 남겨둠 (사용자가 직접 작성)

초안 출력 후 "위 내용을 채워서 커밋하시면 됩니다." 라고 안내해줘.
