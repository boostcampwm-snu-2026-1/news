# Works

주차별 작업 디렉터리. 한 주차 = 한 디렉터리. 새 스펙이 들어오면 다음 주차 디렉터리를 즉시 만든다.

## 구조

```
works/
  week1/
    plan.md       # 목표 · 결정 사항 · 체크리스트 · 의존관계 · 병렬 그룹
    review.md     # 체크리스트 항목별 리뷰 기록 (구현 후 작성)
    ...           # 필요한 추가 산출물(메모, 다이어그램, 스크린샷 등) 자유롭게
  week2/
  ...
```

- 디렉터리 이름은 `weekN` (zero-pad 없음, `week1` `week12`).
- `plan.md`, `review.md`는 표준 파일. 그 외 파일은 자유롭게 추가 가능.
- 진행 중 주차는 `plan.md` 상단 `Status: in-progress`, 완료 시 `done`.

## plan.md 구성

각 주차 plan은 다음 섹션을 갖는다:

1. **메타** — Status, Spec(원본 PDF/문서 경로), Started/Completed 일자
2. **목표** — 1~2 문단으로 무엇을 만드는지
3. **결정 사항** — 새로 정한 스택/아키텍처와 근거
4. **체크리스트** — 한 항목 = 한 커밋 단위. 항목 번호가 그대로 feature list 번호가 됨
5. **의존관계** — 항목 간 선후 관계. 텍스트 그래프 또는 인접 리스트
6. **병렬 그룹** — 동시 진행 가능한 항목 묶음 (subagent 분배 기준)
7. **검증** — 완료 판정 기준
8. **회고** — 완료 후 추가

## review.md 구성

체크리스트 항목 단위로 리뷰 기록:

- 각 항목 구현 직후, 커밋 직전에 review 작성 (워크플로: 설계 → 구현 → **리뷰** → 커밋)
- 리뷰는 코드 품질, 스펙 합치, 회귀 가능성, 테스트 적합성 등을 점검
- 리뷰에서 발견된 수정사항은 **같은 커밋에 포함** (별도 후속 커밋 X). 리뷰는 커밋 단위 안의 단계.

## CLAUDE.md와의 분리

- **CLAUDE.md** = 프로젝트 전범위 영구 규칙 (디자인 토큰, 스택, 커밋/워크플로 규칙 등). 모든 주차에 적용.
- **works/weekN/** = 그 주차의 일시적 컨텍스트.
- 주차 진행 중 발견한 영구 규칙은 CLAUDE.md로 승격 (Stop 훅이 일부 자동화).
