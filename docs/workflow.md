# 뉴스스탠드 개발 워크플로우

## 기본 원칙
- AI는 함께 설계하고 리뷰하는 동료로 사용한다.
- 구현은 체크리스트 번호 하나씩 잘게 나누어 진행한다.
- 설계가 바뀌면 코드보다 먼저 문서를 수정한다.

## 반복 개발 흐름
1. `docs/checklist.md`에서 이번에 작업할 번호를 하나 선택한다.
2. 해당 기능의 목적, 완료 조건, 화면 영향 범위를 3줄 이내로 메모한다.
3. AI에게 설계 검토 또는 구현 초안을 요청한다.
4. 코드를 직접 확인하며 구조, 이름, 재사용성, 접근성을 점검한다.
5. 실행 화면 또는 결과를 확인하고 수정 사항을 반영한다.
6. 커밋 메시지에 체크리스트 번호와 학습 메모를 남긴다.
7. PR 본문에 이번주 목표 대비 진행 상황을 업데이트한다.

## AI에게 요청할 때의 예시
- `#5 공통 레이아웃을 먼저 설계하고 싶어. 헤더/메인/섹션 구조를 나눠줘.`
- `#6 뉴스 카드 컴포넌트를 React로 구현해줘. 제목, 카테고리, 이미지, 요약이 필요해.`
- `#10 상세 보기 방식으로 모달과 별도 페이지 중 어떤 구조가 나은지 비교해줘.`

## 커밋 메시지 규칙
- 제목에는 작업 종류와 체크리스트 번호를 넣는다.
- 본문에는 `확인내용`과 `이해 안 됐던 부분`을 반드시 적는다.

## 커밋 메시지 템플릿
```text
feat: #번호 작업 제목

- 확인내용: 이번 커밋에서 확인한 동작, 구조, 판단 근거
- 이해 안 됐던 부분: 헷갈렸던 개념, 다시 확인한 내용, 추가로 알아본 점
```

## 커밋 예시
```text
feat: #6 뉴스 카드 컴포넌트

- 확인내용: 카드 배치와 제목 줄 수 제한 방식을 확인하고 컴포넌트 분리를 진행함
- 이해 안 됐던 부분: 이미지 비율 유지 방식이 헷갈려서 object-fit 동작을 다시 확인함
```

## PR 작성 기준
- PR 본문에 이번주 학습 목표를 먼저 적는다.
- 완료 작업 목록에는 실제로 끝난 것만 적는다.
- 가장 막혔던 순간, 새로 알게 된 것, 다르게 한다면? 항목을 빠뜨리지 않는다.
