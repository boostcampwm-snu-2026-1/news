# 10주차 검증 기록

## 검증 대상

- 언론사 셀 클릭 시 리스트 뷰로 전환되는지 확인
- 구독 버튼 클릭이 리스트 오픈으로 이어지지 않는지 확인
- 리스트 닫기와 그리드 보기 버튼이 같은 상태 초기화를 수행하는지 확인
- FieldTab 진행률이 6초 단위로 기사와 분야를 순환하는지 확인
- 구독 탭이 비어 있을 때 빈 상태가 깨지지 않는지 확인
- 탭 키보드 이동과 포커스 표시가 유지되는지 확인
- 프로덕션 빌드가 통과하는지 확인

## 검증 방법

1. `npm run build`로 번들 생성 오류를 확인한다.
2. 개발 서버에서 다음 수동 시나리오를 확인한다.
   - 전체 언론사 첫 셀 클릭 후 리스트 화면 진입
   - 닫기 버튼 클릭 후 그리드 복귀
   - 구독하기 버튼 클릭 후 셀이 열리지 않고 구독 배지만 갱신
   - 내가 구독한 언론사 탭에서 해지 후 페이지 범위 유지
   - 리스트 화면에서 분야 탭을 마우스와 키보드로 변경
3. PR 본문에는 위 검증 대상과 실제 확인 결과를 기록한다.

## checklist-20 수동 UI 검증 기록

| 시나리오 | 확인 방법 | 결과 |
| --- | --- | --- |
| 앱 진입 | `http://127.0.0.1:5173/` 요청 | 200 응답 확인 |
| 프로덕션 빌드 | `npm run build` 실행 | 통과 |
| 전체 언론사 셀 클릭 → 리스트 진입 | `GridCell`의 `onOpen` 호출과 `App`의 `viewMode="list"` 전환 경로 확인 | 통과 |
| 리스트 닫기 → 그리드 복귀 | `PressOpen`의 닫기 버튼이 `handleCloseOpen`을 호출하는 경로 확인 | 통과 |
| 구독 버튼 클릭 시 리스트가 열리지 않음 | `SubscribePill`에서 `event.stopPropagation()` 적용 확인 | 통과 |
| FieldTab 키보드 이동 | `ArrowLeft`, `ArrowRight`, `Home`, `End` 처리와 포커스 이동 로직 확인 | 통과 |
| FieldTab 진행률 순환 | `App`의 100ms interval, 6000ms 진행률, 기사/분야 순환 로직 확인 | 통과 |

브라우저 자동화 도구가 설치되어 있지 않아 클릭 자동화 대신 개발 서버 응답, 빌드, 이벤트 연결 경로를 함께 확인했다. Headless Edge 스크린샷 검증은 Windows 권한 문제로 생성되지 않아 결과에 포함하지 않았다.

## checklist-21 접근성 점검 기록

| 점검 항목 | 확인 및 보완 |
| --- | --- |
| 상단 탭 구조 | `TabBar`가 `role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls`를 사용함 |
| 콘텐츠 패널 연결 | 상단 탭 패널은 `aria-labelledby`로 현재 범위 탭과 연결됨 |
| 분야 탭 구조 | `FieldTab`이 `role="tablist"`, `role="tab"`, `aria-selected`, `aria-controls`를 사용함 |
| 분야 탭 패널 연결 | `PressOpen` 기사 패널에 활성 `FieldTab` id를 `aria-labelledby`로 연결함 |
| 키보드 이동 | 상단 탭과 분야 탭 모두 `ArrowLeft`, `ArrowRight`, `Home`, `End` 이동을 지원함 |
| 그리드 셀 조작 | 언론사 셀은 `tabIndex={0}`와 `Enter`/`Space`로 리스트 열기를 지원함 |
| 구독/해지 버튼 의미 | 구독 버튼은 `aria-pressed`로 구독 상태를 알리고, 해지 버튼은 단일 실행 버튼으로 읽히도록 보완함 |
| 현재 기사 표시 | 현재 강조 기사는 `aria-current="true"`로 표시함 |
