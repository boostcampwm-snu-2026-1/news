# PR 본문

## 이번 주 나의 목표

뉴스스탠드의 핵심 사용 흐름을 설계 문서 기준으로 이해하고, 첫 개발 범위를 안정적으로 구현할 수 있는 기반을 만든다. 이번 주 목표는 전체 언론사 그리드, 구독/해지 상호작용, 리스트 뷰 진입에 필요한 데이터 구조와 컴포넌트 경계를 명확히 정한 뒤, 화면 검증 가능한 단위로 구현을 반복하는 것이다.

## 이번 주 학습 방법

- `design_spec.pdf`, `design_config.pdf`를 먼저 읽고 화면 상태, 디자인 토큰, 컴포넌트 규칙을 체크리스트로 분해한다.
- Next.js 16.2.4는 기존 지식과 다를 수 있으므로 코드 작성 전 `node_modules/next/dist/docs/`의 App Router 관련 문서를 확인한다.
- 기능 번호 단위로 브랜치/커밋 흐름을 관리하고, 각 커밋 본문에 확인내용과 이해가 안 됐던 부분을 기록한다.
- 구현 후 `npm run lint`와 Chrome 확인을 반복해 화면이 디자인 문서의 상태와 어긋나지 않는지 점검한다.

## 확인한 설계 기준

- 데스크톱 1280x720 캔버스, 콘텐츠 폭 930px를 기준으로 한다.
- 기본 화면은 헤더, 자동 롤링 뉴스 티커, 탭/뷰 토글, 6x4 언론사 그리드로 구성된다.
- 주요 인터랙션은 언론사 hover 시 구독/해지 버튼 노출, 구독 탭 전환, 페이지네이션, 리스트 뷰 자동 진행이다.
- 강조 색상 `#7890E7`은 구독 수 배지와 활성 진행 탭에만 사용한다.
