# 뉴스스탠드 개발 체크리스트

## 체크리스트 작성 방식
- 형식은 `번호 + 작업명 + 목적 + 주차 + 상태`로 관리한다.
- 모든 커밋 메시지는 관련 체크리스트 번호를 `#번호` 형태로 참조한다.
- 체크리스트는 기획이 바뀌면 추가, 수정, 삭제할 수 있다.

## 이번주 학습 목표
- 일반적인 소프트웨어 개발 흐름을 설계 -> 구현 -> 검증 순서로 직접 반복한다.
- AI를 구현 보조가 아니라 설계 합의와 리뷰를 함께하는 동료로 활용한다.
- Gemini, Claude 같은 AI Agent 도구를 사용할 때 상태 흐름과 완료 기준을 먼저 정의하는 습관을 만든다.

## 이번주 개발 범위
- 이번주에는 `#4`부터 `#16`까지를 우선 진행한다.
- 목표는 PDF 기획/디자인을 Markdown 참고 문서로 정리하고, 상태 흐름이 있는 React 뉴스스탠드 UI와 검증 체계를 함께 만드는 것이다.

## 이번주 검증 메모
- `npm test`로 페이지 계산과 오픈 뷰 자동 진행 로직을 검증한다.
- `npm run build`로 타입 검사와 프로덕션 번들 생성이 되는지 확인한다.
- hover 전용 동작은 `:focus-within`으로 키보드 포커스에서도 동일하게 드러나게 한다.
- `prefers-reduced-motion` 감지 시 티커와 자동 순환을 멈추도록 처리한다.

## 체크리스트 활용 메모
- 구현 전에는 반드시 체크리스트 번호 하나를 기준으로 상태 흐름과 완료 조건을 먼저 적는다.
- 커밋 메시지에는 체크리스트 번호, 확인내용, 이해 안 됐던 부분을 함께 기록한다.
- 다음 작업을 시작할 때는 완료/예정 상태를 다시 갱신한다.
